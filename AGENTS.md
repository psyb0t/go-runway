# go-runway

Unofficial Go client for the Runway API, generated with oapi-codegen. If you only want to use the client from an agent, read [.agents/skills/go-runway/SKILL.md](.agents/skills/go-runway/SKILL.md) instead; this file is about changing the code.

## Architecture

Data flow: `scripts/fetch-spec.sh` (downloads `https://docs.dev.runwayml.com/openapi.json` to `api/openapi.json`) → `scripts/fix-spec.sh` (jq patches, writes `api/openapi.fixed.json`) → oapi-codegen with `config.yaml` → `types.gen.go`, then with `config.client.yaml` → `client.gen.go`.

- `gen.go`: package doc and the `go:generate` steps, in the order above.
- `types.gen.go`: models, enums and union types. Generated.
- `client.gen.go`: `Client`, `ClientWithResponses`, request builders and response parsers. Generated.
- `client_test.go`, `example_test.go`: black-box tests against `httptest` servers.

## Stack

- Go 1.26.9, one package at the module root.
- oapi-codegen and golangci-lint run through `go tool`, pinned in `go.mod`.
- Runtime dependency: `github.com/oapi-codegen/runtime`.

## Layout

- `*.go`: the package.
- `scripts/`: spec fetch and patch, lint and security scan scripts the Makefile runs.
- `api/`: the downloaded spec. Gitignored, never committed.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec, patch it, regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The spec inlines every schema, so its `oneOf` discriminators cannot be mapped and oapi-codegen rejects them. `fix-spec.sh` drops them, which means the generated `As...` methods do not check the variant. Read the discriminating field first.
- `X-Runway-Version` is required on every operation with a single constant value. `fix-spec.sh` removes it from the operations so callers set it once in a request editor. If Runway adds a second version value, revisit that.
- The typed `...WithResponse(ctx, body)` methods take a `...JSONRequestBody`, a named type that drops the union's `MarshalJSON`. For a union body they send `{}`. Callers must use `...WithBodyWithResponse` with marshaled JSON.
- Variant numbering (`...Body0`, `...Body1`) follows spec order. A spec update that reorders variants changes which number means which model.
- `make generate` always downloads the current spec, so the CI pipeline skips the drift check. Regenerate locally and commit the result.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
